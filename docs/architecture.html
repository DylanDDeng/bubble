Bubble 是一个会自己动手的「编码助手」。它能读代码、改文件、跑命令、上网查资料——但每一步都在你掌控之中。下面我们一步步看它脑子里到底发生了什么。

01 — 它到底是什么

一个会用工具的助手

普通聊天 AI 只会「说」，Bubble 还会「做」。你给它一句话，它会自己思考要不要动手、用哪个工具、做完看结果、再决定下一步——就像一个能上手的同事，而不只是个问答机器人。

🧑‍🔧
打个比方：把 Bubble 想成一位新来的得力工程师。你说「帮我把版本号升级一下」，他不会只回你一句话，而是先翻开文件看看、动手改、跑一遍测试，遇到要动真格的操作（删文件、跑命令）还会先问你一声。这一整套「想—做—看—再想」的能力，就是 Agent。
💬

听懂你说的话

把你的需求和整个对话历史交给大模型，让它理解当前要解决什么。

🛠️

自己动手用工具

读写文件、执行命令、搜索代码、上网查资料……23 个内置工具随取随用。

🔁

看结果再继续

每用完一个工具，就把结果喂回模型，循环往复，直到把事情真正办成。

02 — 工作循环

它脑子里的「转圈圈」

Bubble 干活不是一锤子买卖，而是不停地转圈：思考 → 动手 → 看结果 → 再思考。下面这个圈会一直转，亮起来的就是它当前在做的事。一旦不再需要工具，它就跳出循环、给你最终答复。

03 — 工具调用流转 ★

一次工具调用的「接力赛」

这是整个系统最核心的一环。关键点是：模型自己不动手，它只是「下单」说要用某个工具，由内核当「调度员」去解析、审批、执行，再把结果送回模型。点下面的按钮，看这个包裹怎么一站站传递。

04 — 流式输出

为什么字是一个个蹦出来的

你会发现 Bubble 的回答是实时「流」出来的，而不是憋很久一次性甩给你。文字、思考过程、工具调用全都被切成小碎片（事件）即时推送，所以你能边看边等，体验顺滑。下面是一段真实交互的还原：

一句话总结：整个系统就是一条「事件流水线」。模型每吐一点内容、每发起一次工具调用、每跑完一步，都会发出一个事件；终端界面和飞书机器人只管「订阅」这些事件并画出来——所以同一个内核能同时驱动多种界面。
05 — 记忆管理

对话越聊越长，怎么办？

模型的「记忆」（上下文窗口）是有限的，但对话会越积越多。Bubble 会自动「整理书桌」：把很久以前那些又长又占地方的工具结果折叠成一句摘要，腾出空间给新内容，同时保留关键信息。看下面——旧的工具结果会自动收起来。

06 — 模型适配

想换哪个大模型都行

Claude、GPT、DeepSeek……各家模型的接口五花八门。Bubble 在中间加了一层「翻译官」，把它们统统翻译成内部统一的格式。所以对核心逻辑来说，背后是谁家的模型并不重要——随时可换。

07 — 安全闸门

谁来踩刹车？

让 AI 自己跑命令、改文件听起来有点吓人。Bubble 用三种「档位」把控制权交还给你：从「凡事先问」到「全自动放行」，按场景自由切换。无论哪档，明确禁止的操作（deny 规则）永远优先拦截。

default · 默认

日常档。改代码自动放行；但跑命令这类敏感操作会按规则询问你。

👍 适合大多数开发场景
plan · 规划

只看不动手。它只会读和查，先把方案写给你，你点头了才真正执行。

🧭 想先听方案、不想它乱改时用
bypass · 放行

全自动，不打扰你。需要专门的命令行开关才能开启。

🤖 自动化脚本 / 受信环境专用

09 — 工具清单

它都有哪些「工具」

这是 Bubble 的全套「双手」。标签里：只读 表示安全、规划模式也能用；写 会改动你的东西；审批 表示动手前要过你这关。

📁 读写文件
工具属性用途（大白话）
read只读翻开文件看内容
write写 审批新建或整篇覆盖文件
edit写 审批精准替换某段文字，最安全的改法
glob只读按文件名规律找文件
grep只读在代码里全局搜关键词
⚡ 执行与服务
工具属性用途（大白话）
bash写 审批跑终端命令，带超时保护
start_server写 审批启动本地开发服务器
stop_server只读关掉服务器
server_status / server_logs只读看服务器起没起、看日志
🤝 协作 · 检索 · 联网
工具属性用途（大白话）
spawn_agent / wait_agent只读派一个「分身」去后台干活并等它完成
send_input / close_agent只读给分身发指令 / 让它收工
tool_search / skill_search只读按需查找并解锁更多工具 / 技能
skill只读加载某个专项技能
question只读 审批反过来向你提问
exit_plan_mode只读把方案交给你审批
web_search / web_fetch只读上网搜索、抓取网页内容
memory_search / memory_read_summary只读翻查长期记忆
lsp审批像 IDE 一样做代码诊断与重构
